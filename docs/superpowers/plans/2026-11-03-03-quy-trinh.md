# Kế hoạch 03 · Quy trình 15 task: dữ liệu, bộ điều phối, workflow, khóa sửa

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mỗi đơn có 15 task (`order_task`) mở / đóng đúng tiền đề, điều kiện áp dụng, trả lại, tự duyệt, Close-lost và SLA ngày làm việc; mọi thao tác ghi `order_event` không sửa được; đơn bị khóa sửa sau khi gửi duyệt — tất cả kiểm ở máy chủ, chạy được trên sandbox. Màn hình quy trình là Kế hoạch 03b.

**Architecture:** `src/flow/` là thư viện thuần: `tasks.ts` (bảng 15 task, tiền đề, điều kiện áp dụng), `calendar.ts` (ngày làm việc T2–T6, tình trạng hạn), `advance.ts` (`advanceOrder`: trạng thái hiện tại → các thay đổi task / đơn / sự kiện), `sla.ts` (`sweepSla`). Bundle thành `config/code/advance_order.js` và `config/code/sla_sweep.js` bằng `scripts/build-code.mjs`. Người làm task chỉ đổi `status` / `outcome` / `reason` của task mình giữ; các workflow chạy bằng `automation_principal` (trigger) làm phần còn lại: `init_order_tasks` (đơn được tạo), `advance_order` (task đổi trạng thái), `close_lost_order` (đơn chuyển Close-lost), `sla_sweep` (theo lịch).

**Tech Stack:** TypeScript, Vitest, esbuild, `@reflexify/agentflow-app-builder` `sdk-v0.7.0`, `@reflexify/agentflow-sdk/testing`.

**Spec:** `docs/superpowers/specs/2026-11-02-pl-agentflow-design.md` (Thiết kế) — mục 3 (C1, C5, C6), 6.3, 7.2, 8, 13.6. Đặc tả `docs/source/spec.md` Module 6 (FR-6.1–6.10), Phần 4.6 (BR-40–BR-4C). Lộ trình: các mục "Lưu ý cho 03" và "Để cho 03".

**Đã kiểm ở các kế hoạch trước (dùng nguyên):** workflow người dùng khởi chạy phải chạy bằng chính họ → mọi tự động đi qua trigger + `automation_principal`; mỗi workflow tối đa một trigger; một bước binding chỉ là ref / tpl / lit (danh sách cấu hình thành nhiều input); output `lit(...)` của End bị từ chối lúc cài (F-10); rule không so được trường với người đang ghi khi tạo (F-11) — `in_field` không thấy giá trị mới; `$bind: viewer.id` bị từ chối trong rule ghi; bản ghi API mang trường trong `body`; sau thay đổi `src/module/` chạy `pnpm build` trước `pnpm test`.

- Bảng task, tiền đề, điều kiện áp dụng, SLA lấy **nguyên** Đặc tả Module 6 + BR-40, BR-41, BR-47 (tiền đề theo BR-41: t22, t23 ← t11 · t31 ← t22, t23 · t40, t44 ← t31 · t42 ← t40, t44 · t41, t45 ← t42 · t51 ← t41 · t53 ← t45 · t61 ← t45, t53 (+ t51 khi `customer_prepays`) · t62 ← t41 (+ t51 khi `customer_prepays`) · t71 ← t61, t62 · t72 ← t71).
- Giai đoạn: GĐ1 t11 · GĐ2 t22, t23 · GĐ3 t31 · GĐ4 t40, t44, t42, t41, t45 · GĐ5 t51, t53 · GĐ6 t61, t62 · GĐ7 t71, t72.
- Áp dụng (BR-40): có dịch vụ (`order.has_service`) → t22, t62; có hàng hóa (`order.has_goods`) → t23, t44, t45, t53, t61; t31 bắt buộc khi doanh thu > `pl_setting.auto_approve_limit` (300 tr) hoặc `has_goods` hoặc P&L chưa đạt ngưỡng; ngược lại t31 tự duyệt (`skipped`, kết quả `auto_approved`). Task không áp dụng → `not_applicable`; xét lại mỗi lần chạy cho task còn `blocked` / `not_applicable` (nội dung đơn đổi trước khi gửi duyệt).
- Một task "xong" khi `status ∈ {done, skipped, not_applicable}`.
- SLA (BR-49, Thiết kế 13.6): `due_at` = lúc mở + `sla_days` ngày làm việc T2–T6 (bỏ T7, CN; không có lịch nghỉ lễ — ghi chú cho Admin); `sla_days = 0` → không theo dõi; t11 tính từ lúc tạo đơn / lần trả lại gần nhất. Tình trạng: `on_time`, `due_soon` (còn < 24 giờ), `overdue`; khi xong: `done_on_time` / `done_late` + `late_days`.
- Giờ: lưu ISO UTC; "ngày làm việc" tính theo múi giờ `Asia/Ho_Chi_Minh` (UTC+7, không đổi giờ mùa hè).
- Trả lại chỉ ở t22, t31 (BR-43), bắt buộc lý do; "Yêu cầu sửa dự thảo" chỉ ở t42, mở lại t40 / t44, bắt buộc lý do; "Không áp dụng" do người làm chỉ ở t53 (BR-47).

- Khóa sửa (Thiết kế 7.2, BR-23): khi `order.status ≠ draft`, người (trừ automation, Admin) không sửa được trường nghiệp vụ của `order`, không tạo / sửa / xóa `order_line`, giá dòng, `order_finance`; vẫn chuyển được đơn sang Close-lost trước khi ký HĐ KH (t41).
- Mọi entity mới `access.mode = "restricted"`, nhãn tiếng Việt; sau mỗi thay đổi `config/`: `pnpm build && pnpm exec agentflow-app types`; `config/code/*.js` sinh tự động.

```ts
export interface TaskRec { id: string; task_code: TaskCode; status: TaskStatus; outcome: TaskOutcome | null; reason: string;

export interface AdvanceInput { order: FlowOrder & { id: string; created_at: string; approved: boolean; approved_at: string | null;

  tasks: TaskRec[]; slaDays: Record<TaskCode, number>; autoApproveLimit: number; now: string;
  /** Issues of validateOrder(…, 'submit') — the server's own check of a submission (BR-42). */ submitIssues: { path: string; message: string }[]; }
export interface TaskChange { id: string | null; task_code: TaskCode; expect_status: TaskStatus | null; set: Partial<TaskRec> }
export interface AdvanceResult { creates: TaskChange[]; updates: TaskChange[];

  events: { task_code: TaskCode | null; action: EventAction; note: string }[]; }
export type EventAction = 'auto_approved' | 'reopened_missing_fields' | 'returned_processed' | 'revise_processed' | 'approved' | 'completed_order';

```
  `id: null` trong `creates` (task mới). Chỉ đưa vào `updates` những task thực sự đổi; `order` chỉ chứa trường đổi.

Quy tắc, theo thứ tự trong một lượt (lặp tới khi ổn định trong lượt, để mở dây chuyền t31 tự duyệt → t40, t44 trong cùng lượt):

2. **Close-lost** (`order.status = close_lost`) → mọi task `open` / `blocked` → `cancelled`; dừng.
3. **Trả lại** (t22 hoặc t31 `done` với `returned`) → t11 `open` (`opened_at` = now, `due_at` mới, `outcome` / `done_at` xóa), mọi task khác không phải `not_applicable` → `blocked` (xóa `outcome`, `reason`, `opened_at`, `due_at`, `done_at`); đơn `status: draft`, `stage: 1`, `approved: false`; sự kiện `returned_processed` (ghi lý do của task trả lại).
4. **Yêu cầu sửa dự thảo** (t42 `done` với `revise`) → t40, t44 (nếu áp dụng) `open` lại (hạn mới), t42 `blocked`; sự kiện `revise_processed`.
5. **Gửi duyệt** (t11 vừa `done` với `submitted` khi đơn đang `draft`): nếu `submitIssues` không rỗng → t11 `open` lại, sự kiện `reopened_missing_fields` (note = các đường dẫn thiếu, cách nhau bởi dấu phẩy); ngược lại đơn `status: in_progress`, `pl_requested_at: now`.
6. **Áp dụng**: task `blocked` ↔ `not_applicable` theo `applies` (chỉ trước khi task mở).
7. **Mở / đóng**: task `blocked` có mọi `predecessors` ∈ `FINISHED` → `open`, `opened_at` = now, `due_at` theo SLA. Riêng t31 khi mở mà `!needsApproval` → `skipped`, `outcome: auto_approved`, sự kiện `auto_approved`. Task vừa `done` mà chưa có `done_at` → `done_at` = now, `due_state` / `late_days` theo `dueState` (`done_on_time` / `done_late`).
8. **Đơn**: `stage` = giai đoạn nhỏ nhất còn task chưa ∈ `FINISHED ∪ {cancelled}` (BR-4B; hết → 7); `approved` = GĐ1–3 đều xong (lần đầu → `approved_at: now`, `pl_requested_at: now` để chốt P&L — Thiết kế 13.6, sự kiện `approved`); `contract_signed` = t41 `done`; `pending_roles` = vai trò của task `open` (không trùng, theo thứ tự bảng); mọi task xong → `status: done`, sự kiện `completed_order`.
